# 自动化与合规边界

## 推荐架构顺序

1. **用户授权的可见浏览器**：适合单篇与小批量读取，也是默认方案。
2. **本机持久浏览器 helper / MCP**：复用一个专用资料目录，统一登录健康检查、链接净化、低频队列、去重、临时缓存清理与沉淀。首次登录和平台安全验证仍由用户完成。
3. **官方开放接口**：仅在平台未来提供与个人笔记、收藏或喜欢相匹配的正式授权能力时接入。

不把逆向接口或签名脚本作为回退方案。社区爬虫和非官方 MCP 只能用于理解架构与兼容性，不能视为平台授权或稳定性保证。

## 允许的可靠性措施

- 仅处理用户本人明确给出的链接、收藏或喜欢范围。
- 使用同一台设备、同一专用浏览器资料目录和正常可见登录。
- 单线程或低并发增量读取；每批任务设置明确数量上限。
- 按笔记 ID 去重，已成功读取的内容不重复请求。
- 遇到登录页、验证码、安全提示、限流或账号异常立即停止，并记录可恢复状态。
- 对页面结构变化使用显式失败和人工复核，不猜测补全。
- 日志只保留任务状态、笔记 ID、干净链接和错误类型，不记录凭据、完整页面响应或私人浏览器数据。
- 媒体与中间文件按 TTL 清理；沉淀内容仅保存用户要求保留的阅读记录。

## 不支持的规避行为

- 反向或伪造平台签名、令牌和私有请求。
- 设备指纹伪装、自动验证码识别或绕过安全检查。
- 账号池、代理池、IP 轮换或模拟大量用户行为。
- 隐藏浏览器自动化痕迹、规避平台追踪或测试风控阈值。
- 抓取未授权账户、评论、用户信息或超出用户请求范围的数据。

出现此类需求时，解释账号、法律、维护和数据安全风险，并回到用户授权的可见浏览器或官方接口方案。

## 最小健康检查

批量读取前依次确认：

1. 当前使用的是预期的专用浏览器资料目录。
2. 打开一个用户授权的目标笔记后，实际内容区域能取得正文或媒体。
3. 页面没有登录、验证码、安全限制或账号异常提示。
4. 任务数量和沉淀目的地已经由用户明确。

任一检查失败都不得进入批量循环。
